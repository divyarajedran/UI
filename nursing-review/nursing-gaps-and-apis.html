Nursing Gaps & API Spec

This page describes the complete doctor ↔ nurse working flow we need, then lists every gap blocking it on the web and mobile, split into doctor side and nurse side. It ends with the API contract: what exists today, what must change, and what's new.

What we need

The complete working flow (target)

Every step below must work for both web and mobile, because both call the same APIs. The red "today" line under each step shows what is broken or missing now. The key idea: the doctor never has to open the nurse console to see nursing work, and the nurse never has to open the EMR to see the doctor's orders.

IP flow: admission to discharge

Doctor
Admission request with structured nursing orders

Vitals frequency, I/O monitoring, diet, activity, fall precautions, "notify if" thresholds.

Today: one free-text instructionToNurse, which nurses never see.
System
Admit, allocate bed, notify floor nurses

Admission tasks generate once on the server. Nurses on duty for that floor get a push notification.

Today: tasks generate twice (client + server) and there's no push.
Nurse
Scan bed → admission assessment

Access is allowed only for the allotted floor. The nurse records the admission vitals, Braden, Morse, pain score, nutrition screen, allergies and belongings.

Today: no scan, no floor check, no Braden or Morse scale, and the ICU assessment form can't be saved.
Doctor
Orders: medicines, investigations, diet, nursing

Each order becomes a nursing item: medicines become MAR doses, labs become sample tasks, diet goes to the kitchen, and nursing orders become tasks.

Today: only medicines reach the nurse, and only from the console page. GENERATE_ORDER is never called.
Nurse
Acknowledge each new order

The doctor sees "Seen by Priya 09:12".

Today: doesn't exist.
Pharmacy
Dispense, then generate MAR doses

Doses are created from medicine_prescription with the correct ward and branch.

Today: ward is null on almost all rows, and prescriptions from the older page create no doses.
Nurse
Bedside care each shift

Vitals, MAR (given, held or refused, with a reason), I/O, diabetic chart, meal consumption, structured notes and tasks. Everything is saved with the nurse's ID.

Today: two MAR paths, nurse_id is null or 0 on some saves, and meal consumption is stored only in MOP.
System
Alerts

Out-of-range vitals, held or refused doses, missed doses, or a meal refused twice push an alert to the treating doctor and the charge nurse.

Today: no alerts reach the doctor, and overdue tasks never escalate automatically.
Doctor
Nursing tab on the round

One view with vitals trend, MAR today, I/O balance, diet eaten and kcal, notes, tasks, last handover and order acknowledgements.

Today: the doctor sees MAR only inside the nurse console. Tasks, diet and handover aren't visible anywhere.
Nurse
Shift handover (SBAR)

The outgoing nurse sends a per-patient SBAR, and the incoming nurse acknowledges it before starting.

Today: patient notes are lost on save, nurse IDs are 0, and there's no read or acknowledge screen.
Nurse
Transfer or discharge

Covers the nursing discharge checklist, MAR reconciliation, stopping the diet, and returning medicines.

Today: discharge tasks work, but the summary uses admission vitals only.

OP flow: check-in to post-consult

System
Check-in adds the patient to the OP nurse queue

A token is issued, and the patient is routed to the nurse station for the doctor's location.

Today: patients are added manually. Check-in doesn't add them to the queue, and location filtering is dropped.
Nurse
Triage: vitals and assessment

Vitals (including blood sugar), allergies, pain, fall risk, nutrition screen. Everything is saved to the same visit vitals record the doctor reads.

Today: vitals are split across two stores, sugar type is dropped, nurse_id is null, and there are no range checks in the app.
Doctor
Case sheet shows everything the nurse captured

Vitals, allergies, arrival time, psychosocial answers, pain and fall risk, with a "Vitals ready" badge in the doctor's queue.

Today: allergies and psychosocial answers are never shown, and queue vitals probably aren't either.
Doctor
OP procedure orders

Injection, dressing and nebulization orders create OP nurse tasks.

Today: doesn't exist.
Nurse
Complete the procedure → billing + doctor

Records what was done, when, and by whom. Billing is triggered.

Today: doesn't exist.
Non-negotiables

Rules every API must follow

Identity from the token, never from the request body

nurse_user_id and created_by come from the JWT or the server session. Today the nurse ID comes from the DoctorId cookie (null for nurses) and nursing notes send created_by from the browser.

Location access enforced in SQL

Every nurse read or write passes through fn_NurseCanAccessVisit(@nurse_user_id, @visit_reportid, GETDATE()). Charge nurses and the Nursing Superintendent (NS) can read all patients, but writes still follow the roster or an approved cover.

One store per fact

Vitals go to ip_vitalsmonitoring_details (IP) and the visit vitals record (OP). MAR goes to medication_delivery_schedule through the nurse console path only. Diet consumption is mirrored into HMS.

No hard deletes of clinical data

Vitals, fluids and notes use soft delete (is_deleted, deleted_by, reason) with an audit record. Records can't be edited after discharge (enforced on the server, not only in JS).

ChangeNurseConsole/NurseConsole_MAR · Dml "ADM"
Request
{ "Dml_Indicator":"ADM", "dose_id":88213,
  "visit_reportid":55120, "status":"GIVEN",   // GIVEN|HELD|REFUSED|NPO|DELAYED
  "reason_code":null, "site":"L forearm", "batch_no":"CFX2231",
  "qty":1, "vitals_json":null, "access_grant":"eyJ…" }
Server rules
  • Nurse comes from the token.
  • Rejects with 403 if the grant is missing, expired or for another bed.
  • reason_code is required unless the status is GIVEN.
  • Raises a doctor alert for HELD or REFUSED on critical medicines.
ChangeNursingAutomation/ShiftHandover · Dml "I" / "ACK" / "S_PENDING"
Request (I)
{ "Dml_Indicator":"I", "ward_id":31, "outgoing_shift":"MORNING",
  "patients_json":[{ "visit_reportid":55120,
     "situation":"Day 3 pneumonia, febrile 38.6",
     "background":"DM2, penicillin allergy",
     "assessment":"SpO2 95% on 2L, ate 50% lunch",
     "recommendation":"Repeat temp 16:00, CBC pending" }] }
Fixes
  • Replaces patients.toString() (sends [object Object]).
  • Outgoing and incoming nurse IDs come from the roster.
  • ACK sets acknowledged_at, which today is set when the handover is sent.
  • S_PENDING returns the handovers waiting for the incoming nurse.
ChangeIpDietV2/MarkConsumption
Add

After MOP succeeds, insert a row into ip_diet_consumption (visit_reportid, meal_slot, order_id, consumed_pct, kcal_est, protein_est, recorded_by, recorded_at). NursingSummary and the timeline read from this table.

Why

Today, consumption, calories and protein exist only in the external MOP service. Neither the doctor nor reports can see them.

ChangeIpmanagement/Vitalsmonitoring · NursingNotes · Fluids
Changes
  • Created-by from the token. Add source (WEB or MOBILE).
  • DEL becomes a soft delete with a reason.
  • Vitals: add grbs and o2_flow. The response adds alerts[] when values cross the doctor's thresholds.
  • Notes: add note_category (GENERAL, SBAR, INCIDENT, PROCEDURE), plus reviewed_by and reviewed_at.
Access

A nurse-role user must hold a bed-access grant, or pass the allocation check, for this visit_reportid.
